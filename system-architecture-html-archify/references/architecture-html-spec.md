# 系统架构设计 HTML 规范（Archify 版）

## 目标

根据需求、代码、参考图和补充说明生成可交互、可追溯、可本地浏览的系统架构设计。冲突优先级：用户说明 → 已确认需求/设计 → 代码与公共组件 → 参考图 → 通用原则 → 推断。

## 页面与文件

`index.html` 是总入口，`api.html` 使用本地 Swagger UI，`openapi.json` 是 HTTP 契约唯一事实源，`architecture-data.js` 是跨页面业务索引，`archify/` 保存图册源 JSON 和交付 HTML。

主页面至少覆盖：总览、逻辑/部署架构、技术选型和部署运维、流程、时序、ER、API、业务名词、决策、风险与待确认。每个区域有稳定 ID、导航、折叠、Hash 定位和键盘访问。

## 图册

整体架构、部署拓扑、流程、时序、生命周期和数据流使用 Archify。每张图保留 JSON + HTML，并在 `diagramRefs` 登记。不得加载其他图形运行时或把 Archify SVG 复制到主页面。

## 页面体验

图册卡片显示图名、类型、状态、来源数量和打开入口。可用同源 iframe；iframe 必须有标题、失败降级和独立打开链接。Archify HTML 自己负责主题、搜索、聚焦、关系追踪、缩放和导出，主页面不叠加同名控制器。

表格、名词、模块、决策和风险支持鼠标/键盘下钻；关闭抽屉恢复焦点。页面整体无横向溢出；仅表格等局部容器可滚动。不只用颜色表达状态。

## 追溯和一致性

所有对象使用稳定、带类型前缀的 ID，关联只保存 ID。代码证据记录仓库相对路径、符号或行号。图形 ID、统一数据、OpenAPI `operationId` 和页面 Hash 必须互相可解析。

## 验收

运行本技能校验器；对每张图运行 Archify validate/deliver/visual-check；通过本地静态服务器检查页面、图册、API 深链、键盘、窄屏、控制台和网络请求。分别报告静态校验、artifact、自动浏览器证据和人工视觉复核。
